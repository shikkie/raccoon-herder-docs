Herder

The Herder is a separate process that spawns dens. A den is one raccoon-herder cell (image + workspace + agents). This is not the den daemon. Do not put compose/k8s clients in daemon/. Do not mount docker.sock into a den.

herder den create   →  mint token (+ optional LiteLLM key), spawn den
                    →  wait GET /api/health and /api/ready
                    →  print open_url (?token=) once
herder den open     →  same URL again from the store (no second LiteLLM key)
herder den stop     →  git probe; refuse if dirty/unpushed; else stop; volumes kept
herder den rm       →  same git check; remove workload; volumes kept unless --wipe
herder den logs
herder den list
herder onboard      →  first super-admin (local CLI, no public signup)
herder demo-seed    →  demo orgs, quotas, and every dashboard role

--runtime host|kube|swarm. Public install is not available yet; this page is the product shape, not a setup recipe.

State lives in HERDER_STATE_DIR (default ~/.local/state/raccoon-herder/herder), mode 0600. Optional LiteLLM: HERDER_LITELLM_URL + HERDER_LITELLM_MASTER_KEY. Skip minting when the URL is unset.

Dashboard roles

The den has no user table. The Herder dashboard does: cookie login, orgs, quotas, and three roles.

Role Sees Typical job
super_admin Every org Invite people, set org ceilings, spawn anywhere
org_admin One org Invite members, force-terminate, take over dens
user Own dens in that org Spawn / stop / open within quota

Org ceilings cap the whole org (dens, CPU, memory, disk). A member can also have a tighter user quota. Launch flags (allow_shell, pair, generic) are per org; a den only gets them if both the org and the spawn form allow it.

Force-skip of the git probe (stop / terminate / rebuild) is an admin action. On the phone UI it lives inside those modals, not on the dens list.

Floorplans

A floorplan is a spawn recipe: agent, git, first prompt, CPUs / memory / disk, /shell, skip-bootstrap, and env vars (helpers plus free-form keys). Secret values stay in Mongo; GET never returns them. Edit a saved plan on the Floorplans page; leave a secret field blank to keep the stored token.

Save as floorplan on Spawn writes the same fields from the modal (env included). Empty secret boxes are omitted so they do not wipe tokens.

Den rebuild

Each spawn stores a recipe (env, agent, LLM, flags). Rebuild on a den: same git dirty check as terminate (or Force + reason in the modal), stop the container keeping volumes, then spawn again with the same name, id, and env on the current flavor image. Use this after a base-image rebuild.

Dens created before recipes existed cannot rebuild — terminate and spawn once from a floorplan.

Den images (super_admin)

The Images nav lists flavored tags (raccoon-herder:local-grok / -claude / -copilot), whether they are present, last built time, and size. Rebuild runs scripts/build-den-images.sh on the Herder host. Then Rebuild each den to pick up the new tag.

Resources, users, metadata

Knob Meaning
--cpus --memory --pids-limit --workspace-size Per-den caps. Disk on Docker is quota accounting (named volumes); kube uses PVCs.
--user UID[:GID][:NAME] Den/agent user (default 10001 raccoon)
--herder-user Daemon/web user (default 10000 herder)
--packages OS packages at init via den-pkg; that den is not read-only

Dashboard OS packages on spawn and floorplans is the same knob (gh, ripgrep, ffmpeg, jq, …). It is not extra env: Herder stamps RACCOON_OS_PACKAGES plus the apt-compatible legacy RACCOON_APT_PACKAGES, and the den runs den-pkg as root before clone bootstrap. Package names are tokens only ([a-z0-9.+-]+); the Ubuntu 24.04 archive must ship them (GitHub CLI is gh when that package is mirrored). --package-proxy URL stamps a validated http(s) proxy/cache for apt today and dnf/apk future bases; by default Herder uses HERDER_PACKAGE_PROXY / RACCOON_PACKAGE_PROXY or a host apt proxy from /etc/apt/apt.conf.d when packages are requested. | --mcp-file | Stamps ACP mcpServers | | metadata.json | Cloud-init analog at /run/herder/metadata.json |

The den user cannot read /opt/raccoon-herder on Herder-spawned dens. --host-volume / --insecure-bind are operator-only.

Git probe before rm

den stop / den rm / dashboard Rebuild GET {origin}/api/workspace/git. The Herder never docker exec git.

Workspace Result
Not git, or clean and fully pushed Teardown proceeds
Uncommitted and/or unpushed (including no upstream) Refuse, exit 1
Den down, /ready failed, timeout, missing token Refuse unless --force

Volumes: stop and rm keep named volumes; rm --wipe deletes them. Bind mounts are never wiped.

Egress

--egress-mode open|lock|lock-audit|lock-inspect plus --dns. Lock is fail-closed. Dens get isolated networks. See Security.
