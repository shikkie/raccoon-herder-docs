Herder

The Herder is a separate process that spawns dens. A den is one raccoon-herder cell (image + workspace + agents). This is not the den daemon. Do not put compose/k8s clients in daemon/. Do not mount docker.sock into a den.

herder den create   →  mint token (+ optional LiteLLM key), spawn den
                    →  wait GET /api/health and /api/ready
                    →  print open_url (?token=) once
herder den open     →  same URL again from the store (no second LiteLLM key)
herder den stop     →  git probe; refuse if dirty/unpushed; else stop; volumes kept
herder den rm       →  same git check; remove workload; volumes kept unless --wipe
herder den logs
herder den list
herder onboard      →  first super-admin (local CLI, no public signup)
herder demo-seed    →  demo orgs, quotas, and every dashboard role

--runtime host|kube|swarm. Public install is not available yet; this page is the product shape, not a setup recipe.

State lives in HERDER_STATE_DIR (default ~/.local/state/raccoon-herder/herder), mode 0600. Optional LiteLLM: HERDER_LITELLM_URL + HERDER_LITELLM_MASTER_KEY. Skip minting when the URL is unset.

Dashboard roles

The den has no user table. The Herder dashboard does: cookie login, orgs, quotas, and three roles.

Role Sees Typical job
super_admin Every org Invite people, set org ceilings, spawn anywhere
org_admin One org Invite members, force-terminate, take over dens
user Own dens in that org Spawn / stop / open within quota

Org ceilings cap the whole org (dens, CPU, memory, disk). A member can also have a tighter user quota. Launch flags (allow_shell, pair, generic) are per org; a den only gets them if both the org and the spawn form allow it.

Force-skip of the git probe (stop / terminate / rebuild) is an admin action. On the phone UI it lives inside those modals, not on the dens list.

Operations (quarantine)

Ops in the dashboard is host-wide for super admins and org-wide for org admins. It sets the thresholds that quarantine a den (force-stop + hold so the owner cannot terminate it):

  • control-socket requests per second
  • self-restarts / 10 minutes
  • egress drops / 10 minutes
  • DNS burst (suppressed queries)
  • audit-proxy accepts per second

Crossing 2× a threshold holds the den. Org values override host; blank org fields inherit. Env vars (HERDER_CONTROL_RPS, …) seed the host defaults until someone saves Ops. The control socket picks up changes immediately; a DNS/proxy sidecar keeps the env it was started with until the den is rebuilt.

Floorplans

A floorplan is a spawn recipe: agent, git, first prompt, CPUs / memory / disk / tmpfs size, /rh-shell / /rh-sh, skip-bootstrap, and env vars (helpers plus free-form keys). Secret values stay in Mongo; GET never returns them. Edit a saved plan on the Floorplans page; leave a secret field blank to keep the stored token.

Tmpfs size sets the memory-backed /tmp and $HOME a den boots with (default 256m, matching herder den create --tmpfs-size). Raise it per floorplan for dens whose bootstrap downloads large packages (ML wheels, model weights, …) — pip and friends stage large downloads under TMPDIR before moving them into place, and a full tmpfs surfaces as a truncated "connection interrupted" download rather than an obvious disk-space error. Leave it unset to use the default.

Tmpfs backend picks what that scratch space is actually made of: ram (default, a real tmpfs — fast, but it eats into the host's memory and disappears the moment the den is removed) or disk (a bind-mounted directory under the Herder state dir, backed by the host's real disk). Use disk when a bootstrap's downloads are too large to comfortably fit in RAM even after raising tmpfs size, and the host has fast local storage (NVMe) to spare — herder den create --tmpfs-backend disk on the CLI, or the matching floorplan/spawn field. Disk-backed scratch dirs are cleaned up automatically when the den is removed, same as tmpfs. Not supported in Swarm mode: a Swarm service can be rescheduled to any node, and a bind mount tied to one node's disk would silently break or lose data on reschedule, so Swarm rejects tmpfs_backend: disk outright.

Save as floorplan on Spawn writes the same fields from the modal (env included). Empty secret boxes are omitted so they do not wipe tokens.

Secret files

The Secrets page stores .env (and similar) as client-encrypted envelopes. You type a passphrase in the dashboard; Web Crypto seals the file in the browser; Herder stores ciphertext only. Inject at spawn/rebuild, or edit in place, still decrypts in the tab — a wrong passphrase fails the AES-GCM tag locally. See Security for the sequence. Den home is tmpfs: inject again on rebuild or the dest is gone.

Den rebuild

Each spawn stores a recipe (env, agent, LLM, flags). Rebuild on a den: same git dirty check as terminate (or Force + reason in the modal), stop the container keeping volumes, then spawn again with the same name, id, and env on the current flavor image. Use this after a base-image rebuild.

The public hostname ({name}.den.{domain}) stays the same. A leftover PWA tab on that name keeps polling with a dead session cookie, fills the den's login rate limit, and the next Open can show rate limited even with a fresh ?token=. Close those old tabs, wait about a minute, then Open once. The same thing happens if you spawn a new den that reuses a name you already had open.

Dens created before recipes existed cannot rebuild — terminate and spawn once from a floorplan.

Den images (super_admin)

The Images nav lists flavored tags (raccoon-herder:local-grok / -claude / -copilot / -opencode / …), whether they are present, last built time, and size. Rebuild runs scripts/build-den-images.sh on the Herder host. Then Rebuild each den to pick up the new tag.

The den user cannot read /opt/raccoon-herder on Herder-spawned dens. --host-volume / --insecure-bind are operator-only.

Git probe before rm

den stop / den rm / dashboard Rebuild GET {origin}/api/workspace/git. The Herder never docker exec git.

Workspace Result
Not git, or clean and fully pushed Teardown proceeds
Uncommitted and/or unpushed (including no upstream) Refuse, exit 1
Den down, /ready failed, timeout, missing token Refuse unless --force

Volumes: stop and rm keep named volumes; rm --wipe deletes them. Bind mounts are never wiped.

Egress

Dens get isolated networks, and lock* modes are fail-closed: traffic the policy does not allow is dropped, not logged-and-forwarded. Most of the policy is per-den rules and rule sets you manage from the dashboard; the mode and resolver are operator knobs.

Egress rules on a den

The Egress rules section of a den's edit modal is the per-den outbound ACL — rows of Allow / Deny (network filter on tcp / udp / any with ports) plus Block (DNS) / Redirect (DNS) host rules:

Action Effect
Allow Add a destination to the den's allowlist — hostname or CIDR, optional ports
Deny Drop matching egress. Host / Swarm only — Kubernetes NetworkPolicy cannot express an explicit deny, so on k8s you get default-deny + an allowlist instead
Block (DNS) The den's own DNS answers NXDOMAIN for that name (or a sinkhole A address when one is set)
Redirect (DNS) DNS answers NAME → IP (e.g. pinned.test:10.0.0.7)

Rules save to /api/v1/dens/{id}/egress. The effective ACL for a den is the union in order: system rule sets, org rule sets, then the den's own rules. Host iptables is re-applied on save / start for Docker, Podman, and Swarm.

DNS/proxy sidecar flags still need a rebuild (the sidecar is not SIGHUP'd yet). Dashboard dens inherit HERDER_EGRESS_MODE (default lock); only a super admin can pick a mode at spawn. Floorplans store egress_mode and pass it on spawn (including child floorplans that leave the field blank). Saving a den as a floorplan copies the den's recipe — git token, extra env, and egress mode included — via from_den_id.

Host DNS listener (herder serve :8853)

herder serve binds UDP and TCP 8853 (HERDER_DNS_LISTEN=0 skips it). It never binds host :53. For each lock-family den (and for open with log_dns / org log_open_dns), Herder installs NAT only on that den's bridge: :53 → :8853. Attribution is in-interface + source IP.

On host Docker and Podman the lock-audit sidecar is HTTP only. It does not bind DNS (--http on the proxy port; no --dns 0.0.0.0:53). CONNECT lines drain from a bind-mount into Mongo (den_proxy_events). Kubernetes proxy pods still run sidecar DNS on :53 (no host REDIRECT).

Den detail DNS / Proxy accordions are the per-den log. Network is the org hunt (org admin and super-admin). See Security.

Den control socket (drop + restart)

The den cannot reach the Herder dashboard API (loopback). Herder bind-mounts a Unix socket at /run/herder/control/control.sock. One JSON object per connection (read until EOF; pretty-print is fine), no auth (the socket is only in this den). Full shapes live in the repo as docs-no-gh-pages/DEN-CONTROL.md.

Command Meaning
{"op":"egress"} Imposed mode, allow hosts/CIDRs, DNS, drops, can_restart
{"op":"drop","targets":["github.com"]} or "all":true Shrink only
{"op":"restart"} Ask Herder to force-restart this den

CLI (same calls): herder-den egress, herder-den drop github.com, herder-den drop --all, herder-den restart.

Restart is off unless the org feature allow_restart and the den's spawn checkbox are both on (same grant as /rh-shell). Then can_restart is true. {"op":"restart"} is a forced restart (dirty git does not block). The connection often dies before a reply is read because the den is stopping. Host, Swarm, and Kubernetes all honor restart (stop then start). A drop re-applies iptables on host/Swarm and the den NetworkPolicy on kube. The control socket is a bind-mount on host/Swarm and a same-node hostPath on kube (testable on single-node k3s).

Drop applies live to new connections. Established sockets stay until restart.

Flooding the socket, DNS, or the audit proxy holds the den: Herder force-stops it and the owner cannot terminate it until an org admin or super-admin releases the hold (dashboard Release hold, or POST /api/v1/dens/{id}/release-hold). That keeps evidence on disk while someone investigates.

Rule sets

The Egress page holds named, reusable rule sets: system-scoped (super admins only) or org-scoped, sharing the same rule editor as a den. system sets apply to every den, org sets to every den in that organization, and a den's own rules win on overlap. Copy a set into any den you manage.

Modes and DNS are operator-set

The paranoia ladder (open|lock|lock-vendors|lock-audit|lock-inspect| lock-capture) is operator-set: HERDER_EGRESS_MODE / --egress-mode, or the super-admin spawn control. The resolver (--dns, --dns-block, --dns-redirect, --dns-sinkhole-a/--dns-sinkhole-aaaa, --dns-upstream) stays CLI / env. See Security for what each ladder rung captures and enforces, and the orchestrator manual for the operator flags and machine contract.

Questions from agents

Herder runs agents through ACP over stdio, not through a vendor terminal UI. Questions should arrive as ACP form elicitation and appear as an elicit card in chat. If an agent emits a TUI-only helper such as ask_user_question, no TUI can answer it; Herder displays a warning and the user should reply in the chat composer. Pairing and TUI shortcuts are not part of the Herder interface. Floorplans may also inherit from another floorplan. Choose a Base floorplan when saving a recipe to reuse its authentication env, secret files, packages, egress mode, and other non-empty settings. The derived plan's non-empty values override the base; packages and secret files are combined. Leave agent, git URL, tmpfs, and egress blank on the child to inherit. The base must be visible in the same organization, and inheritance cycles are rejected. GET /floorplans includes an effective object with the resolved recipe (secrets still redacted) so spawn prefills the inherited git URL and mode.

Live egress/jail probes live in the companion repo shikkie/raccoon-escape (not scripts/check.sh). Spawn it with extra env RACCOON_ESCAPE_SUITE=all (default) and RACCOON_ESCAPE_AUTO=1 (default); .raccoon/bootstrap.sh runs the suite on every den boot.

From the Herder host, herder escape-run (or --dry-run) spawns dens for open, lock, and lock-audit without cloning GitHub — a lock den cannot reach github.com, so Herder copies escape.sh / escape/run.py into /workspace from HERDER_ESCAPE_SRC or a sibling raccoon-escape checkout. clone-drop is the extra scenario: spawn lock with a git URL (github.com allowed), clone, then drop github.com and run the suite. supply-chain (in the default --modes list) is lock with github/gitlab/pypi/npm allowed, clone, no drop: dummy C&C HTTPS must fail, dig @8.8.8.8 / dig @1.1.1.1 must be NXDOMAIN from Herder (not a public A), github.com still forwards, and the report's dns-events snapshot must show stolen_dest 8.8.8.8/1.1.1.1. The same run's open den stays unlogged (--log-dns omitted) so a real dig @8.8.8.8 still works. Each suite prints # control-egress JSON from the control socket into the rollup. Then the runner floods the sock to trip quarantine. Needs herder serve. --keep leaves the dens; --no-abuse skips the flood. Private clone for clone-drop / supply-chain: HERDER_ESCAPE_GIT_TOKEN / --git-token, or the git token already on the raccoon-escape demo floorplan (GH_TOKEN / RACCOON_GIT_TOKEN; --floorplan / HERDER_ESCAPE_FLOORPLAN to pick one). After a live run it appends escape-run-test.log in the current directory (gitignored) with a UTC timestamp, each den's imposed egress rules, that den's suite/abuse result, and (for supply-chain) a dns-events snapshot (qname, decision, stolen_dest, rcode — no tokens). --skip-report skips the file.

Ops quarantine mode: log (permissive) audits and throttles but does not hold; enforce holds the den at 2× so the owner cannot delete it.

Use Dependency tree on the Floorplans page to view every visible plan and its descendants. If access to a base plan is later lost (for example after leaving an organization), the derived plan is marked Broken base and cannot be spawned until it is edited to choose an accessible base or None.
