Install

Three shapes: one machine on a LAN, one den in a container, and TLS + WAF in front. Many dens is the Herder.

Host (LAN / VPN)

Self-hosted on a Linux user account. No root for the app itself (systemd --user). Bind is LAN-first. Do not expose the app ports to the public internet.

git clone https://github.com/shikkie/raccoon-herder.git
cd raccoon-herder
scripts/bootstrap-venv.sh
scripts/install-hooks.sh   # optional; runs check.sh on commit
cd web/app && npm install && npm run build && cd ../..

Dev loop: ./dev.sh all then http://127.0.0.1:42069/. That is not the production supervisor.

Ports: 42069 web / PWA, 42070 daemon (WEB_PORT / RACCOON_PORT).

Pair

Loopback can talk without a token. Any other client must present a token, and the server must have one configured.

  1. Put a long random string in .env as RACCOON_TOKEN.
  2. Open http://<lan-ip>:42069/ and paste it (stored as rh_token).
  3. REST uses Authorization: Bearer. Hosted dens: GET /?token= sets an HttpOnly RACCOON_SESSION cookie and redirects the token out of the URL.
  4. Pair a phone from the host: http://127.0.0.1:42069/pair (or ./dev.sh pair). One-time LAN URL, five minutes. Do not expose /pair on the public internet.

ACL: loopback, RFC1918 same-subnet (acl.discover_local), plus acl.allow_cidrs. Add Tailscale 100.64.0.0/10 explicitly. Off-LAN: VPN and a token.

Container den

A den is one isolated copy: UI + API + requested CLIs + a workspace. Token is required. Suggested tag: raccoon-herder:local.

# Edit RACCOON_TOKEN in contrib/docker/cell.env.example first
docker compose -f contrib/docker/docker-compose.yml up --build
# http://127.0.0.1:8080/

scripts/container-smoke.sh   # local build + /api/health + /api/ready

Start systemd / ./dev.sh container entrypoint
Token optional on loopback required
Agents you install on PATH RACCOON_AGENTS → /opt/agents
Workspace any RACCOON_CWD /workspace
LAN discovery on off

Useful ENV: RACCOON_TOKEN, RACCOON_CONTAINER=1, RACCOON_AGENTS, RACCOON_GIT_URL (clone + optional ./dev.sh bootstrap), RACCOON_LLM_BASE_URL / KEY / MODEL. After clone, bootstrap runs unless you skip it. Demo: herder den create --demo clones raccoon-todo, bootstraps, and publishes Vite on host 9998 (second origin; PWA stays on the den web port).

Wait for GET /api/ready 200 before routing users. Kubernetes example: contrib/k8s/. Optional RuntimeClass names (you supply the engine): gvisor / runsc, kata, firecracker. Sandbox the den; do not ask this app to isolate tenants. ENV contract: ORCHESTRATOR.md. Per-CLI keys: AGENT-ENV.md.

Compose hardening: non-root, read-only rootfs, no docker.sock, no privileged. Uid split (herder uid vs den user who cannot read /opt/raccoon-herder) is Herder-spawned only.

Reverse proxy (TLS + WAF)

Do not put phones on :42069 over plain HTTP. Terminate TLS and ModSecurity (OWASP CRS) on nginx; bind the app to loopback; set acl.trusted_proxies so the LAN ACL still sees the phone.

phone -- HTTPS :8443 --> nginx + CRS --> 127.0.0.1:42069 web
                                         127.0.0.1:42070 daemon

Honor X-Forwarded-* only from those proxies. Never trusted_proxies: ["0.0.0.0/0"].

cd contrib/nginx
mkdir -p certs
openssl req -x509 -nodes -days 825 -newkey rsa:2048 \
  -keyout certs/server.key -out certs/server.crt \
  -subj "/CN=raccoon-herder.lan"
docker compose up

Chat bodies look like RCE/SQLi/XSS to generic CRS rules. The example exclusions apply those classes only on /api/ and /ws. Leave scanner and protocol rules on. ModSecurity sees the WebSocket handshake, not later frames.

Walkthrough and rule IDs: REVERSE-PROXY.md.
