Raccoon Herder

Self-hosted chat control plane for coding agents. One Linux process herds Grok, Claude Code, Copilot CLI, Hermes, or a generic shell — from a phone, tablet, or desktop browser.

It is not a terminal in the browser. Agents stay local children (ACP JSON-RPC over stdio, or a PTY fallback). The UI is a React PWA: sessions, markdown chat, tool and approval cards, workspace files, slash skills.

Single-tenant dens

This process is single-tenant. One token, one workspace, one state directory. Many users means many dens, plus an external Herder that spawns them. There is no user table, org directory, or billing inside a den.

Quick start

On a Linux machine you already use:

git clone https://github.com/shikkie/raccoon-herder.git
cd raccoon-herder
scripts/bootstrap-venv.sh
./dev.sh all    # http://127.0.0.1:42069/

Off-loopback clients need RACCOON_TOKEN. Do not port-forward the app ports to the public internet — put TLS (and a WAF) in front.

This site

These pages are the user book. They are compiled on a laptop or den with scripts/build-pages.sh into docs/, then published to shikkie/raccoon-herder-docs (scripts/push-docs.sh). The app repo stays private and does not enable GitHub Pages. There is no Actions workflow that builds docs.

Coding agents start at AGENTS.md and the current Phase 8 handoff under docs-no-gh-pages/. Machine contracts (chat protocol, orchestrator ENV, ACP) live there too — this book excerpts them instead of forking a second spec.
