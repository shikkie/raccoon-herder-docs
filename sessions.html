Session lifecycle

A session is one agent process, one cwd, and a transcript. Several can run at once. Stop keeps metadata; Resume respawns the same id. Delete removes the record.

stateDiagram-v2
  [*] --> starting
  starting --> running
  starting --> auth_required
  auth_required --> running
  running --> stopped: stop / /rh-stop
  stopped --> running: resume
  running --> [*]: delete
  stopped --> [*]: delete

auth_required is for vendor login (ACP authenticate). The PWA shows a sign-in banner. Stop may send ACP session/close; delete/prune may send session/delete.

Join vs Resume vs cancel vs /rh-stop

Action What it does
Join Second client attaches to a running session (session list or pair link). Same process.
Resume Respawns a stopped raccoon session with the same id, agent, and cwd. ACP agents that support session/load pick up the vendor thread; a stale id falls back to session/new.
Cancel turn ACP session/cancel. Session stays running. Optional drop of the follow-up queue. Not a stop.
/rh-stop Stops the active session (same as the Stop control). Keeps metadata.
/rh-delete Opens the existing delete confirm.

New session / /rh-new / /rh-clear spawn a fresh raccoon session with the same agent and cwd. Resume agent session… lists native ACP threads on this host (GET /native-sessions).

Approvals

When the agent needs permission, the daemon emits an approval event. The PWA shows a sticky Allow / Deny bar (plus always-allow / always-deny / allow-all for this session). The turn does not continue until you answer.

sequenceDiagram
  participant U as You
  participant P as PWA
  participant D as Daemon
  participant A as Agent
  U->>P: user message
  P->>D: user_message
  D->>A: session/prompt
  A-->>D: tool / permission
  D-->>P: approval card
  U->>P: allow or deny
  P->>D: approval_response
  D->>A: permission result
  A-->>D: turn continues
  D-->>P: assistant / turn done

Pushover (daemon-side, not Web Push) can wake a phone when an approval or turn-complete happens and the PWA is frozen.

Follow-ups while a turn is live

delivery on a user message is queue, steer, or now:

Mode While a prompt is in flight
queue FIFO until the ACP result. Does not steer. Default on ACP.
steer Inject into the live turn (session/inject or Grok interject). If the method is missing, the daemon queues and says so.
now Cancel the live turn, then send this text as the next prompt. Remaining queued items stay queued.

PTY / heuristic sessions send immediately; steer is rejected there. Stop drops the queue. Cancel can drop one queued bubble by id.

Den git before teardown

The Herder will not stop / rm a den that still has uncommitted or unpushed work unless you pass --force.

flowchart TD
  act[herder den stop or rm]
  probe[GET /api/workspace/git]
  act --> probe
  probe -->|clean and pushed| ok[teardown]
  probe -->|dirty or unpushed| no[refuse, exit 1]
  probe -->|den down / timeout| force[refuse unless --force]

The same payload feeds the PWA den-dirty chip and /rh-git.
