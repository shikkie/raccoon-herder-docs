Chat and ACP

The product UI is markdown chat, not a terminal emulator. Structured events (thinking, edits, tools, approvals, turn done) come from ACP when the CLI supports it. A heuristic PTY parser is the fallback.

Turn flow

sequenceDiagram
  participant U as You
  participant P as PWA
  participant D as Daemon
  participant A as ACP CLI
  U->>P: type a turn
  P->>D: user_message
  D-->>P: chat_ack
  D->>A: session/prompt
  A-->>D: thinking / tool / text
  D-->>P: thinking, tool, assistant_chunk
  A-->>D: session/prompt result
  D-->>P: assistant_message / turn done

Follow-ups (queue / steer / now) are described on Sessions. The daemon is the source of truth: a follow-up is queued only after chat_ack with queued: true (or a 2xx REST post). The queue drains even if no UI is connected.

What you see in the PWA

  • Thinking — collapsed by default when the adapter emits it.
  • Edits / diffs — file changes the agent reported.
  • Tool cards — running and finished tools.
  • Approvals — sticky allow / deny.
  • Token meter — ACP usage plus a live estimate while text is flowing.
  • Skills — type / for agent slash commands from that CLI’s trees.
  • /rh-* — raccoon-only; not sent to the agent.

Raccoon commands: /rh-new, /rh-clear, /rh-shell / /rh-sh, /rh-git, /rh-models, /rh-stop, /rh-delete. Unprefixed /new is an agent skill if the CLI advertised it.

Attachments

Paste, drop, or Attach files and photos (phones also get Camera). Images render in the thread. ACP agents get vision blocks plus a workspace path they can open.
